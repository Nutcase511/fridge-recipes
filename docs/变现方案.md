# 「鲜食记」变现方案

## 一、引言

本文档规划「鲜食记」App 的变现路径。当前产品核心功能：

- 冰箱食材管理（录入、分类、过期提醒）
- 智能菜谱推荐（基于现有食材匹配菜谱）
- 健康管理（饮食记录、营养分析）

变现的核心原则：**在不破坏用户体验的前提下，找到用户自愿付费/看广告的价值点。**

---

## 二、方案选型：激励视频广告

### 2.1 为什么选择激励视频广告

| 维度 | 激励视频 | Banner 广告 | 开屏广告 | 会员订阅 |
|------|---------|------------|---------|---------|
| 用户体验 | ⭐⭐⭐⭐⭐ 用户主动选择 | ⭐⭐ 干扰性强 | ⭐⭐⭐ 可跳过 | ⭐⭐⭐⭐⭐ 无广告 |
| 开发成本 | ⭐⭐⭐ 低（1-2天） | ⭐⭐⭐⭐ 极低 | ⭐⭐⭐ 低 | ⭐⭐⭐ 中等 |
| 收益速度 | ⭐⭐⭐⭐⭐ 立刻见效 | ⭐⭐ 极低 | ⭐⭐⭐ 一般 | ⭐⭐⭐ 需用户量 |
| eCPM | ¥15-50 | ¥1-5 | ¥10-30 | - |
| 适合阶段 | 初期→长期 | 初期 | 中期 | 中后期 |

**结论：激励视频广告是当前阶段性价比最高的变现方式。**

### 2.2 收益估算

```
假设 1,000 DAU，人均观看 3-5 次/天

保守（eCPM ¥15）：1,000 × 3 × 30 × ¥15 ÷ 1,000 = ¥1,350/月
乐观（eCPM ¥40）：1,000 × 5 × 30 × ¥40 ÷ 1,000 = ¥6,000/月
```

## 三、广告点位设计

### 3.1 点位总览

| 优先级 | 点位名称 | 触发场景 | 奖励内容 | 每日上限 | 预计转化率 |
|-------|---------|---------|---------|---------|-----------|
| 🔥 P0 | **高级菜谱解锁** | 用户想看 Pro 菜谱 | 免费查看该菜谱 | 3次 | 最高（刚需） |
| ⭐ P1 | **营养分析报告** | 健康页查看详细报告 | 获取本周详细营养分析 | 3次 | 较高 |
| ⭐ P1 | **采购清单导出** | 菜谱页生成购物清单 | 免费导出/分享清单 | 3次 | 中等 |
| 📌 P2 | **批量录入食材** | 添加食材页 | 一次批量录入10+食材 | 2次 | 中等 |
| 📌 P2 | **菜谱收藏扩展** | 收藏夹已满时 | 增加10个收藏位 | 2次 | 较低 |

### 3.2 P0 核心点位详细设计：高级菜谱解锁

**交互流程：**

```
用户浏览菜谱列表 → 点击「👑 秘制红烧肉（Pro）」
         ↓
弹出解锁面板（半屏卡片）：
┌─────────────────────────┐
│   🔒 Pro 专属菜谱         │
│   「秘制红烧肉」          │
│                          │
│   ┌──────────────────┐  │
│   │ 🎬 看视频免费看   │  │  ← 用户主动选择
│   └──────────────────┘  │
│   ┌──────────────────┐  │
│   │ 💎 开通会员 ¥9.9/月│  │  ← 付费选项
│   └──────────────────┘  │
│   [✕ 再看看]            │
└─────────────────────────┘
         ↓
用户点击「看视频免费看」
         ↓
播放 30s 激励视频（用户不可跳过）
         ↓
播放完成 → ✅ 解锁菜谱 + Toast「今日还剩 2 次」
         ↓
展示菜谱完整内容（用料、步骤、视频）
```

**设计要点：**

- **会员兜底**：已开通会员的用户直接跳过所有广告
- **限次策略**：每天每个点位限 3 次，第二天重置
- **倒计时提示**：视频播放时清晰展示剩余秒数（5...4...3...2...1）
- **完成反馈**：播放完毕后明确展示「✅ 已解锁」

## 四、技术实现方案

### 4.1 架构设计

```
┌──────────────────────────────────────────┐
│              业务层                        │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐  │
│  │ 菜谱详情页│ │ 健康页   │ │ 食材录入页│  │
│  └────┬─────┘ └────┬─────┘ └────┬─────┘  │
│       │            │            │        │
│  ┌────▼────────────▼────────────▼─────┐  │
│  │     useRewardedAd（统一广告调用层）   │  │
│  └────────────────┬───────────────────┘  │
│                   │                      │
│  ┌────────────────▼───────────────────┐  │
│  │       广告状态管理（Pinia）          │  │
│  │  ├─ dailyWatchCount（每日观看次数）  │  │
│  │  ├─ isVIP（会员状态）               │  │
│  │  └─ adLoading（加载状态）           │  │
│  └────────────────┬───────────────────┘  │
│                   │                      │
│  ┌────────────────▼───────────────────┐  │
│  │    wx.createRewardedVideoAd()      │  │
│  │    微信小程序原生激励视频 API        │  │
│  └───────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

### 4.2 封装 Composable（useRewardedAd）

```
useRewardedAd(adUnitId, options)
  → 返回值：
    - loading: 广告是否加载中
    - ready: 广告是否就绪
    - show(): 显示广告
    - reward: 是否获得奖励
    - error: 错误信息
  → 配置项：
    - maxDaily: 每日最多观看次数
    - onReward: 奖励回调
    - onError: 错误回调
```

### 4.3 数据存储

前端用 Pinia + localStorage 存储：

```typescript
// 广告状态 Store
interface AdState {
  dailyWatchCount: {
    premiumRecipe: number   // 高级菜谱
    nutritionReport: number // 营养报告
    shoppingList: number    // 采购清单
    batchInput: number      // 批量录入
    collectionExtend: number // 收藏扩展
  }
  lastResetDate: string     // 上次重置日期（用于判断跨天）
  totalWatched: number       // 累计观看次数（用于统计）
}
```

### 4.4 降级方案（广告加载失败时）

| 失败场景 | 处理方式 |
|---------|---------|
| 广告组件加载失败 | 提示「广告加载中，请稍后重试」，提供重试按钮 |
| 网络异常 | 检测网络状态，提示检查网络连接 |
| 广告拉取超时 | 二次重试，仍失败则展示「今日免费通道」（每天1次） |
| 用户关闭广告未看完 | 不发放奖励，提示「需要看完视频才能获得奖励」 |

### 4.5 数据埋点

需要统计的核心指标：

```
展示次数（impressions）→ 曝光量
完播次数（completed）  → 完成率
转化次数（converted）  → 奖励发放量
日活跃用户（DAU）      → 用户基数
渗透率                → 看广告用户 / 总用户
ARPU                 → 每用户平均收入
```

## 五、常见问题

### Q1：用户量少的时候能有多少收入？

即使只有 100-200 DAU，合理设计下：

```
150 用户 × 40% 渗透率 × 3 次 × 30 天 × ¥20 ÷ 1000 = ¥108/月
```

不多，但能覆盖服务器成本，验证模式的可行性。

### Q2：如何防止用户刷广告？

- 服务端校验奖励发放（防伪造）
- 每日观看次数上限
- 同一广告位 30 秒内不可重复触发

### Q3：后续如何升级变现？

```
广告积累用户 → 推出会员订阅
广告验证需求 → 接入电商佣金
前端数据积累 → 拓展 B 端 SaaS
```

## 六、接入后台 / 数据库分析

关于 todo 中提到的是否需要后台管理和在线数据库，分析如下：

### 6.1 纯前端方案（当前阶段适用）

| 能力 | 实现方式 | 是否够用 |
|------|---------|---------|
| 用户数据 | 微信登录 + 本地 Pinia | ✅ 足够 |
| 食材数据 | 本地存储（Storage） | ✅ 足够 |
| 菜谱数据 | 本地 TypeScript 常量 | ✅ 足够 |
| 广告次数 | Pinia + localStorage | ✅ 足够 |
| 统计分析 | 微信后台自带数据 | ✅ 足够 |

**结论：现阶段完全不需要后端服务和在线数据库。**

### 6.2 什么时候需要后台

```
❌ 不需要后台：
   - 纯看广告变现
   - 本地食材管理
   - 本地菜谱推荐

✅ 需要后台：
   - 用户登录/账号体系（多端同步）
   - 用户生成内容（分享菜谱、评论）
   - 电商交易（对接生鲜平台）
   - 会员订阅管理（支付回调）
   - 云端数据备份
   - 精细化数据分析
```

### 6.3 如果未来需要后台，推荐方案

```
轻量级：Supabase / Firebase（适合 1-5 万用户）
          ├── 在线数据库（PostgreSQL）
          ├── 用户认证
          └── 云函数

中期：Node.js + PostgreSQL + Redis
          ├── 自建后端
          ├── 微信支付对接
          └── 管理后台

成熟期：微服务架构
          ├── 用户服务
          ├── 内容服务
          ├── 广告服务
          └── 数据分析服务
```

**当前建议：先用纯前端上线验证，等 DAU > 5,000 再考虑后台。**

## 八、微信广告接入须知

### 8.1 前置条件

1. 已认证微信小程序
2. 在微信公众平台开通流量主
3. 创建广告位获取 `adUnitId`

### 8.2 广告位申请建议

| 广告位名称 | adUnitId 类型 | 建议 |
|-----------|-------------|------|
| 高级菜谱解锁 | 激励视频 | ⭐ 首批必开 |
| 营养分析报告 | 激励视频 | ⭐ 建议开启 |
| 采购清单导出 | 激励视频 | 📌 可选 |
| 批量录入食材 | 激励视频 | 📌 可选 |

### 8.3 注意事项

- 激励视频广告需要用户主动点击触发，不能自动播放
- 不能诱导用户误点（如把广告按钮做得像关闭按钮）
- 需要在广告回调中验证 reward 是否真实发放
- 遵守微信小程序广告规范，避免违规封禁
